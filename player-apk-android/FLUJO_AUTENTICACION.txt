🌍 CONEXIÓN A INTERNET REQUERIDA EN CADA PASO
═════════════════════════════════════════════════════════════════════════════

APK → RENDER (HTTPS)
   Registro:          POST /api/auth/register-request
   Consulta estado:   GET /api/auth/check-device
   Login verificación: POST /api/auth/firebase-login (si aplica)
   Obtener videos:    GET /api/video/list
   Reproducir video:  GET /api/video/{videoId}/play
   Logs de auditoría: POST /api/watermark/log

RENDER → PostgreSQL (Local en Render)
   Guarda solicitud
   Actualiza estado
   Guarda logs
   Verifica permisos

SINCRONIZACIÓN AUTOMÁTICA (Cron Jobs):
   • Cada hora: Sincroniza catálogo con ambiente de Render
   • Cada día: Genera reportes de reproducciones
   • Automático: Notificaciones cuando hay cambios

═════════════════════════════════════════════════════════════════════════════
💾 DATOS GUARDADOS EN CADA ETAPA
═════════════════════════════════════════════════════════════════════════════

EN LA APK (Android):
   ✓ ID único del dispositivo (fingerprint SHA-256)
   ✓ Email del usuario
   ✓ Token JWT (encriptado)
   ✓ Información del dispositivo (marca, modelo)
   ✓ Logs locales de reproducción

EN RENDER (PostgreSQL):
   ✓ Tabla registration_requests (solicitudes pendientes)
   ✓ Tabla students (usuarios aprobados)
   ✓ Tabla audit_log (cada reproducción)
   ✓ Tabla devices (dispositivos autorizados por usuario)
   ✓ Tabla playback_sessions (sesiones activas)
   ✓ Tabla catalog (videos disponibles)

MARCA DE AGUA (Para identificar piratería):
   ✓ Timestamp de reproducción
   ✓ Email del usuario
   ✓ ID del dispositivo
   ✓ ID del video
   ✓ Si video se filtra → sabes exactamente quién lo hizo

═════════════════════════════════════════════════════════════════════════════
🔐 SEGURIDAD EN CADA PUNTO
═════════════════════════════════════════════════════════════════════════════

EN EL LOGIN:
   ✓ Contraseña nunca se guarda (solo en sesión)
   ✓ JWT con expiración
   ✓ Device binding (máximo 2 dispositivos por usuario)
   ✓ Detección de VPN/Proxy

EN LA REPRODUCCIÓN:
   ✓ FLAG_SECURE: No se puede capturar pantalla
   ✓ FLAG_SECURE: No se puede grabar pantalla
   ✓ Cifrado HLS (Advanced Encryption Standard)
   ✓ DRM Widevine (protección de contenido)
   ✓ Watermark forense invisible
   ✓ Detección de emulador
   ✓ Detección de debugger

EN LA BD:
   ✓ PostgreSQL en Render (encriptado en tránsito)
   ✓ SSL/TLS para todas las conexiones
   ✓ Permisos por rol (admin vs estudiante)
   ✓ Logs de auditoría de todos los accesos

⚡ CASOS ESPECIALES
═════════════════════════════════════════════════════════════════════════════

CASO: El usuario intenta registrarse desde 2 dispositivos

   Dispositivo 1 (teléfono):
      Envía: deviceId = "phone_a1b2c3"
      Status: "pending" → "approved" por admin
      Resultado: ✓ Acceso PERMITIDO

   Dispositivo 2 (tablet):
      Envía: deviceId = "tablet_d4e5f6"
      Status: "not_registered"
      Resultado: ✗ "Este dispositivo no está registrado.
                     Máximo 2 dispositivos por cuenta."

CASO: El estudiante intenta ver un curso que NO está asignado

   APK Envía: GET /api/video/curso_node_video_1/play
   
   Render Verifica:
      - ¿Token válido? SÍ
      - ¿Usuario aprobado? SÍ
      - ¿Tiene permiso para curso_node? NO
   
   Render Responde:
      { error: "No tienes acceso a este curso", code: 403 }
   
   APK Muestra:
      ❌ Este curso no está disponible para ti

CASO: El admin RECHAZA una solicitud

   Admin hace: POST /api/admin/registrations/req_123/reject
   
   Render:
      ✓ Marca como "rejected"
      ✓ Guarda notas del rechazo
   
   APK en siguiente consulta:
      GET /api/auth/check-device → { status: "rejected" }
      
      Muestra:
         ❌ Tu solicitud ha sido RECHAZADA
         Razón: "No proporcionaste información verificable"
         Contacta: admin@tudominio.com
